- 2026-09-23 — Step 10 kernel: `run(until)` fires events at times ≤ `until`, leaves later ones on the heap (a second `run` carries on), and ends with `now = until` (SimPy's convention; §8.1 is silent) → an integral read after the run, like `Resource.busy_slot_ms`, covers the whole window. A `Process` starts through the heap, not inside its constructor, and a granted `Resource.request()` is an event that fires through the heap at the current time → everything created at one instant runs in creation order, keeping ties deterministic. Consequence: a request refused at time t is reported before requests granted at t resume.
- 2026-09-23 — Kernel guards that turn silent modelling bugs into loud errors: `release()` without a held slot raises (a double release in Step 13's `finally` paths would otherwise inflate capacity), yielding a non-Event raises `TypeError`, an event can only `succeed()` once, and a negative `Timeout` raises. No failure events: §8.5 errors are request statuses, not exceptions.
- 2026-09-23 — Step 11: `lognormal_from_percentiles` returns `(mu, sigma)` rather than a sampler. Nodes compute it once and draw with the stdlib's `rng.lognormvariate(mu, sigma)` (= `exp(normalvariate(mu, sigma))`; §8.3 writes `gauss`, the distribution is the same and both are seeded) → no per-event closures (§8.12). Tokens-per-second uses a separate `lognormal_from_p50_p1`, since its given bound is the slow 1st percentile.
- 2026-09-23 — `stream()` accepts only the five §8.2 purposes and raises on anything else → a typo can't silently open a fresh stream. - 2026-09-23 — `graph.py` reads preset ids from `shared/presets/` next to the repo root (`parents[3]`) → Step 19's Dockerfile must copy `shared/` into the image at the same relative place.
- 2026-09-23 — Step 13 requests: `Request.status` is None while a request is in flight and healthy; an error (`rejected`, later `rate_limited`) is set by the node that fails it, and every caller checks `req.failed` after a downstream call, stops its remaining calls and unwinds through its `finally` blocks. The users node calls `finish(now)` at the end: an error stays, otherwise `timeout` if `now > deadline` (exactly on the deadline is on time), else `ok`. A timed-out request still does all its work (§8.5).
- 2026-09-23 — Spans: a node appends its span when its *own* work is done, before any downstream call → spans read in visit order, and a service's `work_ms` never includes downstream time (those have their own spans, so Step 15's attribution doesn't double-count). The load balancer and cache record `queue_ms = 0` (no capacity limit). A request rejected at a node gets no span there.
- 2026-09-23 — Nodes are wired after construction through `Node.downstream` (a list in edge order); Step 16 builds it from `design.edges`. Tests wire nodes by hand and drive them with a stub node, so Step 13 has no `simulate()`.
- 2026-09-23 — A slot is requested outside the `try` and released in its `finally` (`yield grant` sits just before the `try`) → only a slot that was actually granted is ever released, and the kernel's double-release guard stays meaningful.
- 2026-09-23 — `leastConnections` counts in-flight requests per target on the load balancer itself (what it sent and hasn't seen return). Ties are scanned from the round-robin cursor, so idle targets take turns instead of the first target getting everything at low load. `roundRobin` ignores load.
- 2026-09-23 — Service replicas are picked strictly round robin (§8.5), even when the chosen replica is full and another has room → a service can reject while it has spare capacity elsewhere, like a round-robin proxy in front of independent replicas.
- 2026-09-23 — The users node clamps each arrival's wait at 0: after the clock jumps, `now` can land a float rounding error past the next arrival time when two arrivals nearly coincide, and the kernel rejects negative timeouts.
- 2026-09-23 — Step 14 hosted LLM: backoff jitter draws from a sixth rng purpose, `retry`, rather than borrowing `work` → §8.2 separates streams so one extra draw can't shift unrelated numbers; with `work`, every 429 would move all later TTFT samples. Jitter is uniform [0, 500) ms added to `min(8000, 500·2^attempt)` (one base backoff unit; §8.6 only says "plus jitter"). A test pins the independence: a call's latency is identical whether or not it was throttled first.
- 2026-09-23 — The rate limit is a bucket of *permits* (named apart from LLM tokens), holding up to `rateLimitRpm`, starting full and refilled lazily on each call from the elapsed time → no timer process, no events. Every 429 counts in `rate_limit_hits` (retried or not) for Step 15's rate-limit rule; after `maxRetries` retries the request fails as `rate_limited`, with no span and no cost.
- 2026-09-23 — Hosted-LLM span: `queue_ms` is the total backoff wait, `work_ms` is ttft + generation → Step 15's attribution tells "throttled" apart from "slow model". `first_token_at` is set when the ttft ends on a request's first LLM call only. `usd` accumulates per completed call; Step 15 extrapolates it to a month.
- 2026-09-23 — `handle(req)` (a service calling the LLM directly) uses the preset's `defaultPromptTokens`/`defaultOutputTokens`; `call(req, prompt, output)` is the entry point Step 20's agent uses. Presets are read through `graph.presets(file)` (cached `{id: preset}`), which also backs the unknown-preset check.
- 2026-09-23 — Step 15 metrics hooks live in the two shared places, not in each node: `Node` gains `resources` (the slot pools behind utilization and queue: a service's replicas, a database's pool, empty otherwise), `served` and `rejects` counters, and `record(req, queue_ms, work_ms)`, which appends the span and counts it (it replaces the `req.spans.append(Span(...))` line in every node). `Resource.pop_queue_peak()` returns the longest line since the last call. `HostedLlm.rate_limit_hits` became `rejects`: for a hosted LLM a reject *is* a 429, so `NodeSummary.rejects` on an LLM counts 429s (as the fake API already did), and the bottleneck rules read it by kind.
- 2026-09-23 — Buckets: a request's arrival counts where it was created, its outcome (status, latency, TTFT) where it ended. The summary adds up the post-warmup buckets, so a request that arrived during warmup but finished after it has its outcome counted, not its arrival. Requests still in flight when the run stops are arrivals with no outcome. `completed` = ok, `errors` = rejected + rate_limited, `errorRate` = (finished − ok) / finished. Latency percentiles cover *answered* requests (ok + timeout): fast failures would flatter them. Percentiles use `statistics.quantiles(method="inclusive")`. If warmup covers the whole run, the summary uses every bucket (as the fake API did).
- 2026-09-23 — Per-node samples come from a sampler process that wakes at each bucket end. Utilization = busy slot-ms / (slots × bucket width), never clamped; a short last bucket (durationS not whole) uses its real width. Node throughput = `served` per second (a node's own work done); the users node has no span, so it reports 0. A service's queue is the sum of its replicas' peaks, an upper bound on the true peak (exact for one replica; marked `ponytail:`).
- 2026-09-23 — Deviation from §8.8, for accuracy: a downsampled timeline point is **exact**, not approximated. §8.8 already keeps every latency in per-bucket lists, so a merged point takes its percentiles from all of its latencies instead of averaging p50s and taking the max of p99s. Rates are totals over the merged width, utilization is weighted by width, and the queue is the max. Consequence: §8.11's "downsampled percentiles" simplification and the UI's "Percentiles over long runs are approximate" line (`TopBar.tsx`) no longer describe the real simulator. Owner to decide whether to drop them (Step 16 writes `docs/simulation-model.md`).
- 2026-09-23 — Bottleneck rules (`sim/analysis.py`): §8.9's table is a `RULES` tuple of (severity, template), so the messages are the plan's word for word. Findings rank by severity, then table row, then design order; max 5. "Deduplicated" = each rule speaks at most once per node, and the 70% headroom warning is skipped when the 90% capacity rule fired. The reject percentage is of `summary.requests`. The attribution message quotes the larger of the top node's waiting/working share (always a true sentence), while the trigger is their total ≥ 50%. `bottlenecks()` takes a `labels` dict (id → label), not the whole design.
- 2026-09-23 — The growing-queue rule is implemented literally: least-squares slope > 0 over the last half of the timeline, and final queue > 2 × the whole-run median. Known edge: a queue that grows linearly from t = 0 ends at about exactly 2 × its median, so the rule doesn't fire; it fires when overload starts partway through (e.g. a spike). The ≥ 90% capacity rule still flags the from-t=0 case.
- 2026-09-23 — Cost (`sim/cost.py`): one breakdown line per node that costs more than $0 (users, load balancer and agent never have one). Assumptions always include the "repeats all month (30 days)" sentence plus a line that preset prices are estimates. `node_summaries(design, monthly_usd)` takes the per-node costs, so Step 16 computes cost first.
- 2026-09-23 — Step 16 `simulate()` is split in two: `execute(design, config, work_samplers)` runs the simulation and returns the nodes, the `Metrics` and the wall time; `simulate()` wraps it and builds the `RunResult`. Tests that need per-request detail (the queueing-theory proofs, the sampler check) use `execute`; the API (Step 17) only ever calls `simulate`. Order inside `execute`: build every node → wire `downstream` in edge order → `Metrics` (its sampler process must exist before the clock moves) → start the users nodes → `env.run`.
- 2026-09-23 — The test-only sampler override (§16) is `Service.sample_work()`, a method that `execute` replaces per node id through a keyword argument. It is not a contract field and not a `RunConfig` option, so it cannot appear in the OpenAPI schema (a test asserts that). Only `Service` has the seam: M/M/1 and M/M/c are service queues, and nothing else needs exponential work.
- 2026-09-23 — `designHash` is computed from the Pydantic model, not the raw JSON: `model_dump(mode="json", by_alias=True, exclude_none=True)`, positions removed, whole floats written as ints, `json.dumps(sort_keys=True, separators=(",", ":"), ensure_ascii=False)`. `exclude_none` is what makes it match the frontend, where an absent `id`/`role` is `undefined` and is dropped. A test re-states the frontend's `stableStringify` rules independently and compares byte for byte on all three templates.
- 2026-09-23 — `Environment.events` counts processed events, for `engine.events` and `eventsPerSec`. Step 17's cooperative wall-time check (every 10k events) reads the same counter.
- 2026-09-23 — Node kinds with no class yet (`agent`, self-hosted `llm`) raise `NotImplementedError` from `run.build` rather than being approximated. Steps 20 and 21 remove that.
- 2026-09-23 — Queueing-theory precision: one 600 s M/M/1 run has a standard deviation of about 15% around the true mean wait (queue waits are strongly autocorrelated, so 4,000 requests are not 4,000 independent samples). The tests average **100 independent runs** per case, which lands within ~1.5%; measured over seed blocks 1–100, 101–200, 201–300 and 301–400, every block is within 1.6% of theory. This is the "longer run / more replications" fix §18 demands instead of widening the 5% bound. Cost: about 9 s of the suite. M/M/c is one replica with `concurrencyPerReplica = c` (one line, c servers), never c replicas, which would be c separate M/M/1 queues.
