- 2026-09-21 — JSON imports widen string literals, so tsc can't check templates against `Design` → `contracts.test.ts` compares every template node to a type-checked exemplar (same keys, same value types, known enum values, preset ids that exist) → catches `p50` vs `p50Ms` and unknown/missing fields at test time.
- 2026-09-21 — GPU `usdPerHour` in `gpus.json` are rough on-demand numbers instead of Appendix A's `0.0` → a $0 GPU makes the cost card meaningless in demos; all stay `verifiedAt: null` and are labeled "verify".
- 2026-09-21 — §18 said one branch + PR per phase → all work goes straight onto `main`, pushed after each step; `phase-0-ui-shell` deleted after its Step 3 commits were replayed onto main → owner prefers a linear, no-merge workflow. CI runs on pushes to main.
- 2026-09-21 — CLAUDE.md was committed in Step 1 → untracked and gitignored; it stays on the owner's disk in the repo folder (so Claude Code still auto-loads it) but is never pushed again → owner's call.
- 2026-09-21 — §7.4 defines `designHash` as sha256 of canonical JSON but not the exact bytes → `canvas/map.ts` emits JSON with recursively sorted keys, no whitespace, `position` and `undefined` fields dropped, arrays kept in order, other fields (incl. `id`, `name`) kept; hashed with Web Crypto → the backend (Step 9+) must match byte for byte: `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`, with whole-number floats written as ints (JS prints `200`, Python prints `200.0`).
- 2026-09-21 — Step 4 has no store yet → the canvas keeps nodes/edges in React Flow's own state and the editor remounts it on each template load; Step 6's design slice takes over → avoids building a throwaway store one step early.
- 2026-09-23 — §7.6 has no rule for an edge whose source/target doesn't exist (the canvas can't make one, but API callers can) → extra code `EDGE_REF`; such edges are reported once and ignored by the other rules → keeps `sim/graph.py` from crashing on adjacency lookups.
- 2026-09-23 — `LIMIT_RATE` compares the *sum* of each users node's own peak rate with 5,000 req/s → conservative (two spikes at different times over-count) but trivial to mirror byte-for-byte in Python. `LIMIT_DURATION` also covers the 10 s floor from §7.3. The 256 KB body limit is HTTP-only, so it lives in the backend, not `validate.ts`.
- 2026-09-23 — `PARAM_RANGE` bounds come from the §7.2 comments; fields with no stated bound only get the obvious floor (costs ≥ 0, counts ≥ 1, tokens whole). Speculative fields are checked only when `enabled`. Unknown preset ids are `PARAM_RANGE` too (path = the id field). `profileId` only has to be non-empty until profiles exist.
- 2026-09-23 — Graph fixtures are `shared/fixtures/graph/*.json`, each `{description, expect, config, design}` where `expect` is the exact sorted set of codes → Step 12's pytest must assert the same set per file; `valid.json` expects `[]`.
- 2026-09-23 — Inline field errors come from `validate()` (matched by `issue.path`), not from per-field checks in the form → one source of truth for ranges; the inspector strips the "Label: " prefix inline. Emptied number inputs become `NaN` in params, which the validator flags until fixed.
- 2026-09-23 — Inspector edits write straight into the canvas's React Flow node state (still local, see Step 4 entry) → Step 6's design slice takes this over too. Flagged nodes/edges get an `invalid` class styled in theme.css (rust border + ⚠ badge, dashed edge) so status isn't hue-only.
- 2026-09-23 — Step 6: the store's `design` (the §7 contract) is the single source of truth; the canvas renders it through `toFlowNode/toFlowEdge` and turns React Flow changes back into store actions (`moveNode`, `remove`, `select`). React Flow's measured node sizes stay in canvas-local state, since controlled nodes without `measured` are hidden → autosave, validation and `simulate` all read one object; `toDesign` was deleted.
- 2026-09-23 — §11.4's `updateParams(id, patch)` became `updateNode(id, patch)` (patch may hold `label` and/or `params`) → the inspector edits labels too; one action beats two. Added `moveNode`, `select`, and `loads` (a counter bumped by `loadTemplate` that keys the canvas so each load re-fits the view).
- 2026-09-23 — Selection is single (one node *or* edge id in `selectedId`; multi-select key disabled) → matches the inspector, which edits one node. A deselect event clears the selection only if it still names the current id, since React Flow reports "B selected / A deselected" in either order.
- 2026-09-23 — The fake's latency uses Sakasegawa's M/M/c wait approximation `u^(√(2(c+1))−1) / (c(1−u))` × held time instead of §11.5's single-server `base/(1−u)` (identical when c = 1) → with c = batch slots or worker threads, the plain formula made the agent template's p50 ≈ 75 minutes. Utilization is still capped at 0.97.
- 2026-09-23 — The fake seeds mulberry32 with `config.seed XOR first 32 bits of designHash`; its 400–900 ms delay is drawn from the same stream and reported as `engine.wallMs`, so a whole `RunResult` is reproducible. p95 is placed 70% of the way from p50 to p99; self-hosted timing uses fixed 150 ms TTFT / 25 ms per decoded token until profiles exist (Step 22).
- 2026-09-23 — `run()` validates with the run config first and sets `status: "error"` plus `issues` instead of calling the API; a second `run()` while one is in flight is ignored (Step 7's double-click rule, enforced in the store).
